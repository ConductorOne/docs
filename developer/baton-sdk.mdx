This reference documents the public APIs in `baton-sdk` that connector developers use. The SDK follows an inversion-of-control pattern: you implement interfaces, and the SDK calls your methods. For guided walkthroughs, see [Building connectors](/developer/syncing) and [Implementing provisioning](/developer/provisioning).

## Connector builder interfaces

### The connector

Your connector type implements `ConnectorBuilderV2`. It declares the connector's metadata, validates its configuration, and returns one resource syncer per resource type:

```go
type ConnectorBuilderV2 interface {
    MetadataProvider
    ValidateProvider
    ResourceSyncers(ctx context.Context) []ResourceSyncerV2
}

type MetadataProvider interface {
    Metadata(ctx context.Context) (*v2.ConnectorMetadata, error)
}

type ValidateProvider interface {
    Validate(ctx context.Context) (annotations.Annotations, error)
}
```

`ConnectorBuilder` is the older form. It's the same interface, but `ResourceSyncers` returns `[]ResourceSyncer`.

If your connector has a `Close() error` or `Close(ctx context.Context) error` method, the SDK calls it at shutdown.

Don't set capabilities in `Metadata`. The SDK computes them from the interfaces that your syncers implement. See [Capabilities matrix](#capabilities-matrix).

### Wiring a connector

`config.RunConnector` is the standard entry point. It builds the command-line interface from your configuration schema, creates your connector, and runs it:

```go
func RunConnector[T field.Configurable](
    ctx context.Context,
    connectorName string,
    version string,
    schema field.Configuration,
    cf cli.NewConnector[T],
    options ...connectorrunner.Option,
)
```

The `cf` argument is a constructor that receives your generated configuration struct and returns the connector:

```go
type NewConnector[T field.Configurable] func(ctx context.Context, cfg T, opts *cli.ConnectorOpts) (
    connectorbuilder.ConnectorBuilderV2, []connectorbuilder.Opt, error)
```

`RunConnector` wraps your connector with `connectorbuilder.NewConnector` itself. The `[]connectorbuilder.Opt` you return configures that wrapper:

```go
func WithTicketingEnabled() Opt
func WithMetricsHandler(h metrics.Handler) Opt
```

The `connectorrunner.Option` values you pass to `RunConnector` configure the runner. Two you're likely to need are `connectorrunner.WithSessionStoreEnabled()`, covered under [Session store](#session-store), and `connectorrunner.WithDefaultCapabilitiesConnectorBuilderV2`, which lets the `capabilities` command run without full configuration. See [Configuration schema reference](/developer/config-schema) for how to define the schema.

## Syncer interfaces

### ResourceSyncerV2

`ResourceSyncerV2` is the primary interface for syncing data:

```go
type ResourceSyncerV2 interface {
    ResourceType(ctx context.Context) *v2.ResourceType
    List(ctx context.Context, parentResourceID *v2.ResourceId,
        opts resource.SyncOpAttrs) ([]*v2.Resource, *resource.SyncOpResults, error)
    Entitlements(ctx context.Context, resource *v2.Resource,
        opts resource.SyncOpAttrs) ([]*v2.Entitlement, *resource.SyncOpResults, error)
    Grants(ctx context.Context, resource *v2.Resource,
        opts resource.SyncOpAttrs) ([]*v2.Grant, *resource.SyncOpResults, error)
}
```

The paged methods take and return these types:

```go
type SyncOpAttrs struct {
    Session   sessions.SessionStore
    SyncID    string
    PageToken pagination.Token // Token is the page token; Size is the requested page size
}

type SyncOpResults struct {
    NextPageToken string
    Annotations   annotations.Annotations
}
```

**Differences from V1:**
- V2 receives a `SyncOpAttrs` with the page token, the sync ID, and the session store.
- V2 returns a `SyncOpResults` instead of a token string and annotations.

The V1 `ResourceSyncer` has the same four methods. Its paged methods take a `*pagination.Token` and return `(results, nextPageToken string, annotations.Annotations, error)`.

### Optional syncer extensions

These interfaces add behavior to a syncer. The SDK detects them by type assertion.

| Interface | Method | Use for |
|-----------|--------|---------|
| `ResourceTargetedSyncerLimited` | `Get(ctx, resourceId, parentResourceId) (*v2.Resource, annotations.Annotations, error)` | Fetching one resource by ID. Enables `CAPABILITY_TARGETED_SYNC`. |
| `StaticEntitlementSyncerV2` | `StaticEntitlements(ctx, opts) ([]*v2.Entitlement, *resource.SyncOpResults, error)` | Entitlements that don't belong to a specific resource |
| `TypeScopedGrantsSyncer` | `GrantsForResourceType(ctx, resourceTypeID, opts) ([]*v2.Grant, *resource.SyncOpResults, error)` | Listing grants for a whole resource type in one call |
| `TypeScopedEntitlementsSyncer` | `EntitlementsForResourceType(ctx, resourceTypeID, opts) ([]*v2.Entitlement, *resource.SyncOpResults, error)` | Listing entitlements for a whole resource type in one call |

A resource type that carries the `TypeScopedGrants` or `TypeScopedEntitlements` annotation must implement the matching interface, or `NewConnector` fails.

## Provisioning interfaces

The SDK detects provisioning support from these interfaces on your syncers. They are covered in detail in [Implementing provisioning](/developer/provisioning).

| Interface | Methods | Enables |
|-----------|---------|---------|
| `GrantProvisionerV2` | `Grant(ctx, principal *v2.Resource, entitlement *v2.Entitlement) ([]*v2.Grant, annotations.Annotations, error)` | `CAPABILITY_PROVISION` (with `RevokeProvisioner`) |
| `RevokeProvisioner` | `Revoke(ctx, grant *v2.Grant) (annotations.Annotations, error)` | `CAPABILITY_PROVISION` (with a grant provisioner) |
| `AccountManagerLimited` | `CreateAccount(ctx, accountInfo, credentialOptions) (CreateAccountResponse, []*v2.PlaintextData, annotations.Annotations, error)` and `CreateAccountCapabilityDetails(ctx)` | `CAPABILITY_ACCOUNT_PROVISIONING` |
| `ResourceCreator` | `Create(ctx, resource *v2.Resource) (*v2.Resource, annotations.Annotations, error)` | `CAPABILITY_RESOURCE_CREATE` (as part of `ResourceManagerV2Limited`) |
| `ResourceDeleterV2Limited` | `Delete(ctx, resourceId, parentResourceID *v2.ResourceId) (annotations.Annotations, error)` | `CAPABILITY_RESOURCE_DELETE` |
| `CredentialManagerLimited` | `Rotate(ctx, resourceId, credentialOptions)` and `RotateCapabilityDetails(ctx)` | `CAPABILITY_CREDENTIAL_ROTATION` |
| `CredentialIssuerLimited` | `Issue(ctx, input)` and `IssueCapabilityDetails(ctx)` | `CAPABILITY_CREDENTIAL_ISSUE` |

The full interfaces combine a syncer with these methods. `ResourceProvisionerV2` embeds `ResourceSyncerV2`, `ResourceManagerV2` embeds `ResourceSyncerV2`, and `AccountManagerV2` embeds `ResourceSyncerV2` and `AccountManagerLimited`. Each also has a V1 counterpart that embeds `ResourceSyncer` instead.

`CreateAccount` returns one of four response types: `CreateAccountResponse_SuccessResult`, `_ActionRequiredResult`, `_AlreadyExistsResult`, or `_InProgressResult`.

The older `CredentialOptions` form of `CreateAccount` and `Rotate` is rejected at startup. Use `LocalCredentialOptions`.

## Custom actions

Register custom actions through `GlobalActionProvider` on your connector, or `ResourceActionProvider` on a resource builder:

```go
type GlobalActionProvider interface {
    GlobalActions(ctx context.Context, registry actions.ActionRegistry) error
}

type ResourceActionProvider interface {
    ResourceActions(ctx context.Context, registry actions.ActionRegistry) error
}

type ActionRegistry interface {
    Register(ctx context.Context, schema *v2.BatonActionSchema, handler ActionHandler) error
}

type ActionHandler func(ctx context.Context, args *structpb.Struct) (*structpb.Struct, annotations.Annotations, error)
```

Registering any action enables `CAPABILITY_ACTIONS`. The `actions` package also has helpers to read arguments (`GetStringArg`, `GetIntArg`, `GetBoolArg`, `GetResourceIDArg`, and the `Require` variants) and to build return values (`NewReturnValues`). See [Custom actions](/developer/provisioning#custom-actions) for a complete example.

<Note>
`CustomActionManager` and `RegisterActionManager` are deprecated. Use the providers above.
</Note>

## Event feeds

Connectors that stream events from the target system implement `EventFeedsLimited`:

```go
type EventFeedsLimited interface {
    EventFeeds(ctx context.Context) []EventFeed
}

type EventFeed interface {
    ListEvents(ctx context.Context, earliestEvent *timestamppb.Timestamp,
        pToken *pagination.StreamToken,
    ) ([]*v2.Event, *pagination.StreamState, annotations.Annotations, error)
    EventFeedMetadata(ctx context.Context) *v2.EventFeedMetadata
}
```

This enables `CAPABILITY_EVENT_FEED_V2`. A connector built on `ConnectorBuilder` (V1) implements `EventProviderV2`, which combines `ConnectorBuilder` with `EventFeedsLimited`.

## Type builders

### Resource builder

```go
// Create a resource type definition.
func NewResourceType(name string, requiredTraits []v2.ResourceType_Trait,
    msgs ...proto.Message) *v2.ResourceType

// Create a resource ID.
func NewResourceID(resourceType *v2.ResourceType, objectID interface{}) (*v2.ResourceId, error)

// Create a resource.
func NewResource(name string, resourceType *v2.ResourceType,
    objectID interface{}, resourceOptions ...ResourceOption) (*v2.Resource, error)
```

For resource types that carry a trait, use the trait constructors. Each takes a slice of trait options before the general resource options:

```go
func NewUserResource(name string, resourceType *v2.ResourceType, objectID interface{},
    userTraitOpts []UserTraitOption, opts ...ResourceOption) (*v2.Resource, error)
func NewGroupResource(name string, resourceType *v2.ResourceType, objectID interface{},
    groupTraitOpts []GroupTraitOption, opts ...ResourceOption) (*v2.Resource, error)
func NewRoleResource(name string, resourceType *v2.ResourceType, objectID interface{},
    roleTraitOpts []RoleTraitOption, opts ...ResourceOption) (*v2.Resource, error)
```

`NewAppResource`, `NewSecretResource`, `NewScopeBindingResource`, and `NewManagedDeviceResource` follow the same pattern.

**Resource options:**

```go
func WithAnnotation(msgs ...proto.Message) ResourceOption
func WithParentResourceID(parentResourceID *v2.ResourceId) ResourceOption
func WithDescription(description string) ResourceOption
func WithResourceProfile(profile map[string]interface{}) ResourceOption
func WithResourceIcon(assetRef *v2.AssetRef) ResourceOption
func WithResourceStatus(resourceStatus v2.Status_ResourceStatus, details string) ResourceOption
func WithResourceCreatedAt(createdAt time.Time) ResourceOption
func WithAliases(aliases ...string) ResourceOption
func WithNHIType(nhiType v2.NonHumanIdentityTrait_NhiType, detail string) ResourceOption

// Attach a trait to a resource.
func WithUserTrait(opts ...UserTraitOption) ResourceOption
func WithGroupTrait(opts ...GroupTraitOption) ResourceOption
func WithRoleTrait(opts ...RoleTraitOption) ResourceOption
func WithAppTrait(opts ...AppTraitOption) ResourceOption
```

<Note>
`WithExternalID` is deprecated and no longer used. The SDK identifies a resource by its resource type and resource ID.

**Status values:**

| Status | Meaning |
|--------|---------|
| `STATUS_ENABLED` | Active user |
| `STATUS_DISABLED` | Suspended user |
| `STATUS_DELETED` | Soft-deleted user |
| `STATUS_PENDING` | Account creation started, but the account isn't usable yet, such as an invitation that hasn't been accepted |
| `STATUS_UNSPECIFIED` | Unknown status |

**Account types:**

| Type | Meaning |
|------|---------|
| `ACCOUNT_TYPE_HUMAN` | Human user |
| `ACCOUNT_TYPE_SERVICE` | Service account |
| `ACCOUNT_TYPE_SYSTEM` | System account |

This isn't an exhaustive list of option functions. Group, role, app, secret, scope binding, and managed device traits each have their own option functions in the `resource` package.

### Grant builder

```go
// Create a grant that links a principal to an entitlement.
func NewGrant(resource *v2.Resource, entitlementName string,
    principal GrantPrincipal, grantOptions ...GrantOption) *v2.Grant
```

The `principal` is a `*v2.ResourceId` or a `*v2.Resource`. `entitlementName` is the name you gave the entitlement, which becomes its slug.

## Pagination

### Token types

```go
type Token struct {
    Size  int    // Requested page size
    Token string // The token you returned on the previous call
}

type StreamToken struct {
    Size   int    // Page size
    Cursor string // Stream cursor
}

type StreamState struct {
    Cursor  string // Next cursor
    HasMore bool   // More events available
}
```

### Pagination bag

For nested or multi-list pagination:

```go
type PageState struct {
    Token          string
    ResourceTypeID string
    ResourceID     string
}

func (pb *Bag) Push(state PageState)
func (pb *Bag) Pop() *PageState
func (pb *Bag) Next(pageToken string) error
func (pb *Bag) NextToken(pageToken string) (string, error)
func (pb *Bag) Current() *PageState
func (pb *Bag) PageToken() string
func (pb *Bag) ResourceTypeID() string
func (pb *Bag) ResourceID() string
func (pb *Bag) Marshal() (string, error)
func (pb *Bag) Unmarshal(data string) error
```

`pagination.GenBag[T]` is a generic version that holds a stack of your own state type. Create one with `pagination.GenBagFromToken[T](token *pagination.Token)`.

If the API rejects a page token, return `pagination.NewRestartActionError(restartPageToken, reason string)` to restart the call. See [Pagination patterns](/developer/pagination) for usage.

## HTTP client utilities

The `uhttp` package builds HTTP clients that work with the SDK's error handling. It has two layers: an `*http.Client` factory, and a `BaseHttpClient` wrapper that sends requests and decodes responses.

### Create a client

```go
func NewClient(ctx context.Context, options ...Option) (*http.Client, error)

// Options
func WithTLSClientConfig(tlsConfig *tls.Config) Option
func WithLogger(log bool, logger *zap.Logger) Option
func WithUserAgent(userAgent string) Option
func WithTimeout(timeout time.Duration) Option
```

For authenticated clients, `uhttp.NewBearerAuth(token)` and `uhttp.NewBasicAuth(username, password)` return credentials whose `GetClient(ctx, options...)` method builds the `*http.Client`.

### Send requests

```go
func NewBaseHttpClientWithContext(ctx context.Context, httpClient *http.Client,
    opts ...WrapperOption) (*BaseHttpClient, error)

func (c *BaseHttpClient) NewRequest(ctx context.Context, method string, url *url.URL,
    options ...RequestOption) (*http.Request, error)
func (c *BaseHttpClient) Do(req *http.Request, options ...DoOption) (*http.Response, error)
```

| Option type | Functions |
|-------------|-----------|
| `RequestOption` | `WithHeader`, `WithBearerToken`, `WithJSONBody`, `WithFormBody`, `WithNoCache` |
| `DoOption` | `WithJSONResponse`, `WithResponse`, `WithErrorResponse`, `WithRatelimitData` |
| `WrapperOption` | `WithRateLimiter(rate int, per time.Duration)` |

`Do` reads and closes the response body for you. For pagination helpers, see [Pagination patterns](/developer/pagination#link-header).

### Caching, errors, and retries

```go
func CreateCacheKey(req *http.Request, opts ...CacheOption) (string, error)
func ClearCaches(ctx context.Context) error
```

`uhttp` caches successful GET responses and can extract rate limit data from responses when you pass `WithRatelimitData`. It doesn't retry requests. It translates HTTP statuses such as 429, 502, 503, and 504 into the gRPC `Unavailable` status, and the SDK retries calls that fail with `Unavailable` or `DeadlineExceeded`.

## Session store

The session store caches data for the duration of a sync. It's available only to V2 syncers, and only when you enable it:

```go
config.RunConnector(ctx, "baton-acme", version, cfg.Config, connector.New,
    connectorrunner.WithSessionStoreEnabled(),
)
```

Without that option, session store calls return `session.ErrSessionStoreDisabled`.

The store holds byte slices:

```go
type SessionStore interface {
    Get(ctx context.Context, key string, opt ...SessionStoreOption) ([]byte, bool, error)
    GetMany(ctx context.Context, keys []string, opt ...SessionStoreOption) (map[string][]byte, []string, error)
    Set(ctx context.Context, key string, value []byte, opt ...SessionStoreOption) error
    SetMany(ctx context.Context, values map[string][]byte, opt ...SessionStoreOption) error
    Delete(ctx context.Context, key string, opt ...SessionStoreOption) error
    Clear(ctx context.Context, opt ...SessionStoreOption) error
    GetAll(ctx context.Context, pageToken string, opt ...SessionStoreOption) (map[string][]byte, string, error)
}
```

The `session` package wraps it with typed JSON helpers, such as `session.GetJSON[T]` and `session.SetJSON`:

```go
func (g *groupBuilder) Grants(ctx context.Context, res *v2.Resource, opts resource.SyncOpAttrs) ([]*v2.Grant, *resource.SyncOpResults, error) {
    // Read from the cache.
    users, found, err := session.GetJSON[[]User](ctx, opts.Session, "users")
    if err != nil {
        return nil, nil, err
    }
    if !found {
        users, err = g.client.ListUsers(ctx)
        if err != nil {
            return nil, nil, err
        }
        // Store it for later calls in this sync.
        if err := session.SetJSON(ctx, opts.Session, "users", users); err != nil {
            return nil, nil, err
        }
    }

    // Build grants from users.
    return grantsFrom(res, users), nil, nil
}
```

`session` is `github.com/conductorone/baton-sdk/pkg/session`, and `grantsFrom` stands in for your own code. The store limits how much data it holds, so cache only what you need.

## Capabilities matrix

The SDK detects capabilities from the interfaces your syncers implement. It computes them per resource type, and you don't declare them yourself.

| Capability | Detected from |
|------------|---------------|
| `CAPABILITY_SYNC` | `ResourceSyncerV2` or `ResourceSyncer` |
| `CAPABILITY_TARGETED_SYNC` | `ResourceTargetedSyncerLimited` |
| `CAPABILITY_SERVICE_MODE_TARGETED_SYNC` | A connector that supports targeted sync |
| `CAPABILITY_PROVISION` | Grant and revoke provisioners |
| `CAPABILITY_ACCOUNT_PROVISIONING` | `AccountManagerLimited` |
| `CAPABILITY_RESOURCE_CREATE` | `ResourceManagerV2Limited` (or `ResourceManager`) |
| `CAPABILITY_RESOURCE_DELETE` | `ResourceDeleterV2Limited`, `ResourceDeleterLimited`, or a resource manager |
| `CAPABILITY_CREDENTIAL_ROTATION` | `CredentialManagerLimited` |
| `CAPABILITY_CREDENTIAL_ISSUE` | `CredentialIssuerLimited` |
| `CAPABILITY_EVENT_FEED_V2` | `EventFeedsLimited` (or the older `EventProvider`, which the SDK wraps) |
| `CAPABILITY_TICKETING` | `TicketManager` |
| `CAPABILITY_ACTIONS` | Any registered action |

### Common patterns

| Task | Functions |
|------|-----------|
| Create a resource type | `resource.NewResourceType(name, traits)` |
| Create a user | `resource.NewUserResource(name, type, id, []resource.UserTraitOption{resource.WithEmail(...)})` |
| Create any resource | `resource.NewResource(name, type, id, opts...)` |
| Create an entitlement | `entitlement.NewAssignmentEntitlement(resource, name)` |
