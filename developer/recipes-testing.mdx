## Configurable base URL for mocks

**Problem:** Test your connector against a mock server without hitting production.

**Solution:** Add a base URL field to your configuration, and give it a default that points at the real API:

```go
// pkg/config/config.go
var BaseURL = field.StringField(
    "base-url",
    field.WithDisplayName("Base URL"),
    field.WithDescription("Base URL for the API. Use http://localhost:8080 for testing."),
    field.WithDefaultValue("https://api.example.com"),
)

var ConfigurationFields = []field.SchemaField{APIKey, BaseURL}
```

After you run `make generate`, the generated configuration struct has a `BaseUrl` field. Pass it to your client:

```go
// pkg/connector/connector.go
func New(ctx context.Context, cc *cfg.Example, _ *cli.ConnectorOpts) (connectorbuilder.ConnectorBuilderV2, []connectorbuilder.Opt, error) {
    cl, err := client.New(ctx, cc.ApiKey, cc.BaseUrl)
    if err != nil {
        return nil, nil, err
    }
    return &Connector{client: cl}, nil, nil
}
```

**Usage:**

```bash
# Production
./baton-example --api-key $KEY

# Testing
./baton-example --api-key test --base-url http://localhost:8080
```

**Why:** Without a configurable base URL, you can't test without hitting production. That breaks CI and risks exposing production data. See [Define your configuration](/developer/config-schema#define-your-configuration) for how fields become flags.

## Insecure TLS for local testing

**Problem:** Test against a mock server that uses a self-signed certificate.

**Solution:** Add a bool field, and apply it when you build the HTTP client:

```go
// pkg/config/config.go
var Insecure = field.BoolField(
    "insecure",
    field.WithDescription("Skip TLS certificate verification. For local testing only."),
)

// pkg/client/client.go
func New(ctx context.Context, apiKey, baseURL string, insecure bool) (*Client, error) {
    var opts []uhttp.Option
    if insecure {
        // This replaces the default TLS config, so set MinVersion again.
        opts = append(opts, uhttp.WithTLSClientConfig(&tls.Config{
            MinVersion:         tls.VersionTLS12,
            InsecureSkipVerify: true,
        }))
    }

    httpClient, err := uhttp.NewClient(ctx, opts...)
    if err != nil {
        return nil, err
    }

    base, err := uhttp.NewBaseHttpClientWithContext(ctx, httpClient)
    if err != nil {
        return nil, err
    }

    return &Client{http: base, baseURL: baseURL}, nil
}
```

**Usage:**

```bash
./baton-example --api-key test --base-url https://localhost:8443 --insecure
```

**Why:** Mock servers often use self-signed certificates. An `--insecure` flag lets you test without installing a custom certificate authority.

<Warning>
Never use `--insecure` in production. It's strictly for local testing with mock servers.
</Warning>

## Unit-test a resource builder

**Problem:** Verify that a builder lists the right resources, including across pages, without running a full sync.

**Solution:** Call the builder's methods directly with a fake client, and loop until the page token is empty:

```go
func TestUserBuilderList(t *testing.T) {
    ctx := context.Background()
    b := newUserBuilder(newFakeClient())

    var all []*v2.Resource
    token := ""
    for {
        resources, results, err := b.List(ctx, nil, resource.SyncOpAttrs{
            PageToken: pagination.Token{Token: token},
        })
        require.NoError(t, err)

        all = append(all, resources...)
        if results == nil || results.NextPageToken == "" {
            break
        }
        token = results.NextPageToken
    }

    require.Len(t, all, 3)
    require.Equal(t, "Alice", all[0].DisplayName)
    require.Equal(t, "alice-id", all[0].Id.Resource)
}
```

`require` is `github.com/stretchr/testify/require`. Have the fake client return small pages, so the loop crosses a page boundary. Call `Entitlements` and `Grants` the same way, passing the resource under test.

**Why:** Testing the page loop catches token bugs before they reach a real sync. A V2 builder returns its next token in `results.NextPageToken`, and nil results mean the same as an empty token.

## Use the SDK test helpers

The `pkg/test` package has helpers for common checks:

| Helper | What it does |
|--------|--------------|
| `ExhaustResourcePagination`, `ExhaustEntitlementPagination`, `ExhaustGrantPagination` | Page through a syncer until the token is empty, and fail if a page reports being rate limited |
| `GrantsIntegrationTest` | Grants an entitlement, checks that the grant appears, revokes it, and checks that it's gone. Any connector that provisions should pass it. |
| `AssertWasRatelimited`, `AssertNoRatelimitAnnotations` | Check a call's annotations for rate limit signals |

<Note>
These helpers accept the V1 interfaces, `ResourceSyncerLimited` and `ResourceProvisionerLimited`. A V2 builder doesn't satisfy them, so for V2 builders write the page loop yourself, as in the previous recipe.
</Note>

## Run and inspect with the baton CLI

**Problem:** Check a connector end to end against a real or mock API.

**Solution:** Run the connector to produce a sync file, then inspect it with the `baton` CLI:

```bash
./dist/*/baton-example --api-key $KEY --base-url http://localhost:8080 \
  --log-level debug -f sync.c1z

baton resources -f sync.c1z
baton entitlements -f sync.c1z
baton grants -f sync.c1z
baton stats -f sync.c1z
```

To iterate on one part of a sync, limit it:

```bash
# Only sync some resource types.
./dist/*/baton-example --api-key $KEY --sync-resource-types user,group -f sync.c1z

# Skip grants while you work on resources and entitlements.
./dist/*/baton-example --api-key $KEY --skip-grants -f sync.c1z
```

To test provisioning against a sync file, see [Test provisioning locally](/developer/provisioning#test-provisioning-locally).

**Why:** The `baton` CLI reads the same file that C1 would receive, so you see what your connector actually produced, including IDs and parent links.
