C1 provides identity governance for Vanta. Connect your Vanta tenant to sync Vanta login accounts, person groups, and the memberships that link those groups to Vanta accounts.

## Capabilities

|Resource|Sync|Provision|
|-|-|-|
|Vanta accounts|<Icon icon="square-check" iconType="solid" color="#c937ae"/>||
|Person groups|<Icon icon="square-check" iconType="solid" color="#c937ae"/>||
|Group memberships|<Icon icon="square-check" iconType="solid" color="#c937ae"/>||

<Note>
The connector deliberately does not import Vanta's full personnel directory. Personnel records are broader than Vanta login accounts and can otherwise create duplicate or phantom app users in C1. A group membership is synced only when Vanta links the Person record to an actual Vanta account through `userId`.
</Note>

## Prerequisites

- A Vanta account with admin access.
- A dedicated **Manage Vanta** application with the `vanta-api.all:read` scope.
- The application's OAuth client ID and client secret.

<Warning>
Vanta permits one active access token per application. Requesting a new token immediately revokes the previous token. Give each concurrently running connector instance its own Manage Vanta application. The connector does not retry a revoked cached token after a 401; the current sync fails and the next run obtains a new token.
</Warning>

## Create the Manage Vanta application

<Steps>
  <Step>
    Sign in to Vanta, open **Settings** > **Developer Console**, and click **Create**.
  </Step>

  <Step>
    Choose **Manage Vanta** as the application type. Enter a recognizable name and description for the C1 connector.
  </Step>

  <Step>
    Grant the application the read-only `vanta-api.all:read` scope.
  </Step>

  <Step>
    Copy the generated OAuth client ID. Click **Generate client secret**, then copy and securely store the secret.
  </Step>
</Steps>

## Configure the Vanta connector

<Tabs>
  <Tab title="Cloud-hosted">
    <Steps>
      <Step>
        In C1, go to **Integrations** > **Connectors** and click **Add connector**.
      </Step>

      <Step>
        Search for **Vanta** and click **Add**.
      </Step>

      <Step>
        Keep the default **Vanta API origin** for a commercial tenant, or set it
        to `https://api.vanta-gov.com` for Vanta Gov. The connector derives both
        API and OAuth endpoints from this origin. Then enter the **Vanta client
        ID** and **Vanta client secret** from the Developer Console.
      </Step>

      <Step>
        Click **Save**. C1 exchanges the credentials for a read-only Manage Vanta token, validates access with `GET /users`, and starts the first sync.
      </Step>
    </Steps>
  </Tab>

  <Tab title="Self-hosted">
    Follow the on-screen self-hosted instructions and provide:

    - `BATON_VANTA_CLIENT_ID`: the Manage Vanta OAuth client ID.
    - `BATON_VANTA_CLIENT_SECRET`: the Manage Vanta OAuth client secret.
    - `BATON_VANTA_API_ORIGIN`: optional API origin; defaults to `https://api.vanta.com`. Use `https://api.vanta-gov.com` for Vanta Gov. The connector derives both API and OAuth endpoints from this origin.
    - `BATON_VANTA_ALLOW_INSECURE_HTTP`: hidden development-only flag that defaults to `false`. When `true`, it permits only a pathless HTTP loopback origin for local mock probes. Never enable it with real Vanta credentials.
  </Tab>
</Tabs>

## Synced access model

- **Vanta accounts** come from `GET /users`; the Vanta user ID is the stable C1 resource ID. The endpoint returns active accounts only, so inactive accounts disappear from sync rather than transition to disabled.
- **Person groups** come from `GET /groups` and expose a `member` entitlement.
- **Membership grants** come from `GET /groups/{groupId}/people` and use the row's `userId` to reference a Vanta account.
- Personnel rows without `userId` do not produce users or grants. If a group retains a `userId` that is absent from active `/users`, its membership can temporarily lack a matching synced principal.

This connector is sync-only. Adding a group member requires a Person ID that cannot be derived from a Vanta User ID without scanning `/people`. Revocation could recover the Person ID from the target group's current membership rows, but the connector does not expose asymmetric revoke-only provisioning. It requests no Vanta write scope and does not modify accounts, personnel, groups, or memberships.
