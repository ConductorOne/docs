# FireHydrant

The FireHydrant connector syncs identities and access from
[FireHydrant](https://firehydrant.com/), provisions accounts and team
membership through the FireHydrant SCIM 2.0 endpoints, and surfaces
FireHydrant incidents as Baton tickets so access-request workflows can open
and read incidents.

## Synced resources

| Resource | Capabilities |
| --- | --- |
| User | Sync, account provisioning, account deletion |
| Team | Sync, team membership provisioning |
| On-call schedule | Sync (membership and current on-call surface as grants) |

Team resources expose a `member` grant for each membership and a dynamic
`incident-role:<role-id>` entitlement plus matching grant for every member who
has a default incident role on that team. On-call schedule resources expose a
`member` grant for everyone on the schedule and an `on-call-now` grant for the
user with an active shift.

## Ticketing

FireHydrant incidents are surfaced as Baton tickets through a single
`incident` schema. The schema is populated from the live tenant on demand:

- Ticket types come from `GET /v1/severities` (each severity slug is a type).
- Ticket statuses are the fixed set of standard FireHydrant lifecycle
  milestone slugs (FireHydrant exposes no catalog endpoint for milestones;
  org-specific custom milestones will appear on returned incidents but not
  in the schema's status picklist).
- The `priority` custom field is a picklist sourced from `GET /v1/priorities`.
- The `incident_type` custom field is a picklist sourced from
  `GET /v1/incident_types`.

Creating a ticket calls `POST /v1/incidents`, mapping the ticket display name,
description, type (severity), labels (tag list), priority, and incident type
onto the FireHydrant incident contract. Reading a ticket calls
`GET /v1/incidents/{id}` and maps the incident back into the Baton ticket
shape, including the current milestone as the ticket status and a deep link
to the FireHydrant incident page as the ticket URL.

## Configuration

| Field | Required | Description |
| --- | --- | --- |
| `api-token` | yes | FireHydrant bot user API token. Generate one in **Settings > Bot users**. Owner permissions are required for SCIM provisioning. |
| `base-url` | no | Override the FireHydrant API base URL. Defaults to `https://api.firehydrant.io`. |

## Required permissions

The bot user backing the API token must have **Owner** permissions on the
FireHydrant organization so it can call the SCIM 2.0 endpoints used for account
and team membership provisioning. A lower-privileged token can still drive
read-only sync but provisioning calls will fail.
