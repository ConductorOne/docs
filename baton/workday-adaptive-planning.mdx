The Workday Adaptive Planning connector syncs the following resources:

| Resource | Sync | Provision | Delete |

| Accounts | <Icon icon="square-check" iconType="solid" color="#c937ae"/> | <Icon icon="square-check" iconType="solid" color="#c937ae"/> | <Icon icon="square-check" iconType="solid" color="#c937ae"/> |
| Permission sets | <Icon icon="square-check" iconType="solid" color="#c937ae"/> | <Icon icon="square-check" iconType="solid" color="#c937ae"/> | |
| Groups | <Icon icon="square-check" iconType="solid" color="#c937ae"/> | | |

{/* AUTO-GENERATED:END - capabilities */}

The Workday Adaptive Planning connector supports [automatic account provisioning and deprovisioning](/product/admin/account-provisioning). New accounts get a generated password and the permission set you choose. If an account with the same email already exists, C1 links to it instead of creating a duplicate.

<Note>
**C1 can assign permission sets but not remove them yet.** Removing a permission set through the Adaptive Planning API hasn't been confirmed, so revoke requests fail until it is. Remove permission sets in Adaptive Planning directly.
</Note>

<Note>
**Run one permission set change per user at a time.** Assigning a permission set rewrites the user's whole permission set list, so two changes for the same user running at once can undo each other. Re-run the task if a permission set is missing afterward.
</Note>

<Note>
**Instances that sync users from Workday HCM or Workday Financials are not supported**, for sync or provisioning.
</Note>

<Note>
**Instances that use Unified Access Management (UAM) can't have permission sets assigned from C1.** With UAM, permission sets are assigned in Workday and Adaptive Planning turns off assigning them through its API.
</Note>

## Gather Workday Adaptive Planning credentials

The connector signs in as an Adaptive Planning user. Create a dedicated user for C1 so its actions are easy to audit.

<Steps>
  <Step>
    Sign in to Adaptive Planning as an administrator and click **Administration**.
  </Step>

  <Step>
    Under **Users and Permissions**, click **Permission Sets** and create a permission set for C1 with these **Admin Access** permissions:

    - **Users**: needed to read users and groups, create users, and delete users
    - **Permission Sets**: needed to read and assign permission sets
    - **Manage Global User Groups**: needed to read groups and their members
  </Step>

  <Step>
    Click **Users**, create a user for C1 (for example `c1-integration@yourcompany.com`), set a password, and assign the permission set from the previous step.
  </Step>

  <Step>
    Note the user's login and password. If the user can reach more than one Adaptive Planning instance, also note the instance code of the instance C1 should manage.
  </Step>

  <Step>
    Note the API URL for your region. US instances use `https://api.adaptiveplanning.com`. Other regions are listed in Workday's "Adaptive Planning Authentication URLs and IP Addresses" reference.
  </Step>
</Steps>

## Configure the Workday Adaptive Planning connector

<Tabs>
  <Tab title="Cloud-hosted">
    Follow these instructions to use a built-in, no-code connector hosted by C1.

    <Steps>
      <Step>
        In C1, navigate to **Integrations** > **Connectors** and click **Browse connectors**.
      </Step>

      <Step>
        Search for **Workday Adaptive Planning** and click **Add**.
      </Step>

      <Step>
        Choose how to set up the new Workday Adaptive Planning connector:

        - Add the connector to a currently unmanaged app
        - Add the connector to a managed app
        - Create a new managed app
      </Step>

      <Step>
        Set the owner for this connector.
      </Step>

      <Step>
        Click **Next**.
      </Step>

      <Step>
        Find the **Settings** area of the page and click **Edit**.
      </Step>

{/* AUTO-GENERATED:START - config-params
     Generated from config_schema.json. Do not edit manually. */}

      <Step>
        Enter the required configuration:

        - **Username**: Login of the Adaptive Planning user the connector signs in as.
        - **Password**: Password of that user.
        - **Instance code** (optional): Instance to manage when the user can reach more than one. Leave empty to use the user's default instance.
        - **API URL** (optional): Adaptive Planning API URL for your region. Defaults to `https://api.adaptiveplanning.com`.
      </Step>

{/* AUTO-GENERATED:END - config-params */}

      <Step>
        Click **Save**.
      </Step>

      <Step>
        The connector's label changes to **Syncing**, followed by **Connected**. You can view the logs to ensure that information is syncing.
      </Step>
    </Steps>

    **Done.** Your Workday Adaptive Planning connector is now pulling access data into C1.
  </Tab>

  <Tab title="Self-hosted">
    Follow these instructions to use the Workday Adaptive Planning connector, hosted and run in your own environment.

    When running in service mode on Kubernetes, a self-hosted connector maintains an ongoing connection with C1, automatically syncing and uploading data at regular intervals.

    ### Step 1: Set up a new Workday Adaptive Planning connector

    <Steps>
      <Step>
        In C1, navigate to **Integrations** > **Connectors** and click **Browse connectors**.
      </Step>

      <Step>
        Search for **Baton** and click **Add**.
      </Step>

      <Step>
        Choose how to set up the new Workday Adaptive Planning connector:

        - Add the connector to a currently unmanaged app
        - Add the connector to a managed app
        - Create a new managed app
      </Step>

      <Step>
        Set the owner for this connector.
      </Step>

      <Step>
        Click **Next**.
      </Step>

      <Step>
        In the **Settings** area of the page, click **Edit**.
      </Step>

      <Step>
        Click **Rotate** to generate a new Client ID and Secret.

        Carefully copy and save these credentials.
      </Step>
    </Steps>

    ### Step 2: Create Kubernetes configuration files

    Create two Kubernetes manifest files for your Workday Adaptive Planning connector deployment:

    #### Secrets configuration

    ```yaml expandable
    # baton-workday-adaptive-planning-secrets.yaml
    apiVersion: v1
    kind: Secret
    metadata:
      name: baton-workday-adaptive-planning-secrets
    type: Opaque
    stringData:
      # C1 credentials
      BATON_CLIENT_ID: <C1 client ID>
      BATON_CLIENT_SECRET: <C1 client secret>

      # Workday Adaptive Planning credentials
      BATON_WORKDAY_ADAPTIVE_PLANNING_USERNAME: <Login of the Adaptive Planning user>
      BATON_WORKDAY_ADAPTIVE_PLANNING_PASSWORD: <Password of that user>

      # Optional: instance to manage when the user can reach more than one
      BATON_WORKDAY_ADAPTIVE_PLANNING_INSTANCE_CODE: <Instance code>
      # Optional: API URL for your region (defaults to https://api.adaptiveplanning.com)
      BATON_WORKDAY_ADAPTIVE_PLANNING_BASE_URL: <API URL>

      # Optional: include if you want C1 to provision access using this connector
      BATON_PROVISIONING: "true"
    ```

    Run `--help` to see all available configuration flags and environment variables.

    #### Deployment configuration

    ```yaml expandable
    # baton-workday-adaptive-planning.yaml
    apiVersion: apps/v1
    kind: Deployment
    metadata:
      name: baton-workday-adaptive-planning
      labels:
        app: baton-workday-adaptive-planning
    spec:
      selector:
        matchLabels:
          app: baton-workday-adaptive-planning
      template:
        metadata:
          labels:
            app: baton-workday-adaptive-planning
            baton: "true"
            baton-app: workday-adaptive-planning
        spec:
          containers:
          - name: baton-workday-adaptive-planning
            image: public.ecr.aws/conductorone/baton-workday-adaptive-planning:latest
            imagePullPolicy: IfNotPresent
            env:
            - name: BATON_HOST_ID
              value: baton-workday-adaptive-planning
            envFrom:
            - secretRef:
                name: baton-workday-adaptive-planning-secrets
    ```

    ### Step 3: Deploy the connector

    <Steps>
      <Step>
        Create a namespace in which to run C1 connectors (if desired), then apply the secret config and deployment config files.
      </Step>

      <Step>
        Check that the connector data uploaded correctly. In C1, click **Apps**. On the **Applications** tab, locate and click the name of the application you added the Workday Adaptive Planning connector to. Workday Adaptive Planning data should be found on the **Entitlements** and **Accounts** tabs.
      </Step>
    </Steps>

    **Done.** Your Workday Adaptive Planning connector is now pulling access data into C1.
  </Tab>
</Tabs>
