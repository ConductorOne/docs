Point your AI tools at two local endpoints on your laptop, and every model call and outbound HTTPS request they make goes through your organization's Edge Gateway as you. C1 Multipass signs each request with the device session it already holds, so you don't manage provider API keys, and your organization's Edge Gateway policy and audit apply to the traffic.

## How Edge Gateway routing works

C1 Multipass runs a background service on your device. When you turn on Edge Gateway routing, that service opens two endpoints on your device's loopback interface:

| Endpoint | Default address | Use it for |
| :--- | :--- | :--- |
| Inference | `http://127.0.0.1:18080/v1` | An OpenAI-compatible API. Supports `GET /v1/models`, `POST /v1/chat/completions`, `POST /v1/responses`, and `POST /v1/messages`. |
| Egress | `http://127.0.0.1:18081` | An HTTPS proxy (`HTTPS_PROXY`) for tools that make their own outbound calls. |

Both endpoints require a local key, because any process on your device can reach a loopback port. The C1 Multipass command line tool prints the key into your shell's environment for you. The service never logs the key or writes it to disk.

Your C1 admin decides which models and destinations you can reach. The Edge Gateway enforces that policy on every request, not your device.

## Before you begin with Edge Gateway routing

Confirm the following before you start. Egress is the most common gap: it needs your device to trust your organization's Edge Gateway certificate authority (CA).

| Requirement | Who provides it |
| :--- | :--- |
| A Mac with Apple silicon (M1 or later) | You |
| C1 Multipass installed in **/Applications**, connected to your C1 tenant, with this device registered | You |
| Access to at least one Edge Gateway | Your C1 admin |
| For egress: your organization's Edge Gateway CA certificate and its SHA-256 fingerprint | Your C1 admin, or your device management (MDM) profile |

<Note>
Always open C1 Multipass from **/Applications**, not from the downloaded disk image. macOS runs apps launched from a disk image or Downloads from a temporary location, and the C1 Multipass service refuses to take instructions from an app at an unexpected path. If you opened it from the disk image, quit the app, eject the disk image, and open it again from **/Applications**.
</Note>

## Turn on Edge Gateway routing

Turn on routing from the C1 Multipass app. The app must be unlocked to start routing. After it starts, routing keeps running when the app locks.

<Steps>
<Step>
In C1 Multipass, open **Settings** > **General**.
</Step>
<Step>
Turn on **Route AI traffic through Edge**.
</Step>
<Step>
If the app shows **Open Login Items**, click it and allow **C1 Multipass** in macOS System Settings. This lets the C1 Multipass service run in the background.
</Step>
<Step>
**Optional.** If you have access to more than one Edge Gateway, choose one from the **Edge** list.
</Step>
<Step>
If the status shows **Start**, click it.
</Step>
</Steps>

The status line reads **Running at http://127.0.0.1:18080/v1**, and the **Edge** row shows the Edge Gateway in use.

## Install the C1 Multipass command line tool

The command line tool is the only way to read the local key, so install it before you connect a terminal.

<Steps>
<Step>
In C1 Multipass, open **Settings** > **General**.
</Step>
<Step>
Next to **Command line tool**, click **Install**.
</Step>
<Step>
Add the install directory to your `PATH`. C1 Multipass doesn't edit your shell configuration.

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
```
</Step>
<Step>
Open a new terminal window and check the routing status.

```bash
c1-multipass headless edge status
```
</Step>
</Steps>

The status output shows `"running": true` and `"ready": true`, with the inference and egress addresses.

## Connect a terminal to Edge Gateway

Load the endpoint settings into your current shell. Use `eval` so the local key goes straight into the environment instead of your screen or shell history.

```bash
eval "$(c1-multipass headless edge env)"
```

This sets three variables in the current shell:

| Variable | Value |
| :--- | :--- |
| `OPENAI_BASE_URL` | `http://127.0.0.1:18080/v1` |
| `OPENAI_API_KEY` | The local key |
| `HTTPS_PROXY` | `http://c1:<local key>@127.0.0.1:18081` |

Tools you start from this shell now use Edge Gateway. Run the command again in each new shell, and again after the C1 Multipass service restarts, because the local key changes when the service restarts.

To confirm each endpoint has a valid Edge Gateway session, call its health route. The health route doesn't need the key.

```bash
curl -s http://127.0.0.1:18080/_c1/health
curl -s http://127.0.0.1:18081/_c1/health
```

Each returns `{"ok":true}` when ready. A `{"ok":false,"reason":"..."}` response names the problem; see [Troubleshoot Edge Gateway routing](#troubleshoot-edge-gateway-routing).

## Send inference requests through Edge Gateway

The inference endpoint accepts OpenAI-style requests, so any tool or SDK that reads `OPENAI_BASE_URL` and `OPENAI_API_KEY` works without code changes. List the models your Edge Gateway allows:

```bash
curl -s "$OPENAI_BASE_URL/models" -H "Authorization: Bearer $OPENAI_API_KEY"
```

Then call a model from the list:

```bash
curl -s "$OPENAI_BASE_URL/responses" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "<model id>", "input": "Say hello", "store": false}'
```

Requests must use `Content-Type: application/json` and name exactly one model. The endpoint rejects request URLs that carry a query string. Each model's entry in the model list describes the request formats and options it supports.

<Note>
Some clients add query parameters to every request. For example, Claude Code calls `/v1/messages?beta=true`, so don't point `ANTHROPIC_BASE_URL` at the local inference endpoint. Route those clients through the egress endpoint instead, if your Edge Gateway policy allows the provider's API host.
</Note>

## Send outbound HTTPS traffic through Edge Gateway

The egress endpoint is an HTTPS proxy. Edge Gateway inspects the traffic it carries, so it presents certificates issued by your organization's Edge Gateway CA. Your tools must trust that CA, or their requests fail with errors such as `unable to get local issuer certificate`.

### Get the Edge Gateway CA certificate

Your Edge Gateway publishes its CA certificate at a fixed path on your Edge Gateway host. Your C1 admin can give you the host name and the expected SHA-256 fingerprint.

<Steps>
<Step>
Download the CA certificate. `--noproxy '*'` keeps this request off the egress proxy.

```bash
mkdir -p ~/.config/c1-edge
curl -fsS --noproxy '*' -o ~/.config/c1-edge/ca.pem \
  https://<your edge gateway host>/.well-known/timebandit/ca.pem
```
</Step>
<Step>
Print the certificate's fingerprint and compare it with the one your admin gave you. Don't use the certificate if they differ.

```bash
openssl x509 -in ~/.config/c1-edge/ca.pem -noout -subject -fingerprint -sha256
```
</Step>
<Step>
Build a trust bundle that contains your system's root certificates and the Edge Gateway CA. Some destinations pass through Edge Gateway without inspection and present their own certificates, so tools need both.

```bash
cat /etc/ssl/cert.pem ~/.config/c1-edge/ca.pem > ~/.config/c1-edge/bundle.pem
```
</Step>
</Steps>

`~/.config/c1-edge/bundle.pem` now holds the certificates your command line tools need.

### Point your tools at the trust bundle

Most command line tools and language runtimes don't read the macOS Keychain. Set each runtime's trust variable:

| Runtime | Variable | Value |
| :--- | :--- | :--- |
| OpenSSL-based tools | `SSL_CERT_FILE` | `~/.config/c1-edge/bundle.pem` |
| curl | `CURL_CA_BUNDLE` | `~/.config/c1-edge/bundle.pem` |
| Python `requests` | `REQUESTS_CA_BUNDLE` | `~/.config/c1-edge/bundle.pem` |
| Node.js | `NODE_EXTRA_CA_CERTS` | `~/.config/c1-edge/ca.pem` |

Then make a request through the proxy:

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://api.github.com
```

A `200` response confirms the request went through Edge Gateway and your tools trust its CA. A `403` response means your Edge Gateway policy doesn't allow that destination.

### Optional: Distribute the Edge Gateway CA with device management

If your organization manages Macs with an MDM such as Microsoft Intune or Jamf Pro, admins can deploy the CA instead of each user downloading it:

- **Keychain trust** (browsers and apps that use the macOS Keychain): upload the CA certificate as a trusted certificate profile. Only an MDM-delivered profile can mark a root certificate as trusted without a user prompt.
- **Command line trust**: deploy a script that downloads the CA from the path above, checks its fingerprint, and writes the trust bundle. Set the variables from the previous section in the users' shell profile.

## Optional: Turn Edge Gateway on and off per shell

Add two shell functions so one command turns routing and trust on for the current shell, and another turns them off:

```bash
cat >> ~/.zshrc <<'EOF'

# C1 Multipass Edge Gateway routing
edge-on() {
  eval "$(c1-multipass headless edge env)"
  export NO_PROXY="127.0.0.1,localhost"
  export SSL_CERT_FILE="$HOME/.config/c1-edge/bundle.pem"
  export CURL_CA_BUNDLE="$HOME/.config/c1-edge/bundle.pem"
  export REQUESTS_CA_BUNDLE="$HOME/.config/c1-edge/bundle.pem"
  export NODE_EXTRA_CA_CERTS="$HOME/.config/c1-edge/ca.pem"
}
edge-off() {
  unset OPENAI_BASE_URL OPENAI_API_KEY HTTPS_PROXY NO_PROXY \
        SSL_CERT_FILE CURL_CA_BUNDLE REQUESTS_CA_BUNDLE NODE_EXTRA_CA_CERTS
}
EOF
```

In a new shell, `edge-on` routes that shell's tools through Edge Gateway, and `edge-off` returns it to direct connections.

## When Edge Gateway routing stops

Routing keeps running when the C1 Multipass app locks. It stops when you:

- Turn off **Route AI traffic through Edge**.
- Sign out of C1 Multipass or reset the device.
- Restart the device or the C1 Multipass service. Unlock the app to start routing again, then run `eval "$(c1-multipass headless edge env)"` again for the new key.

## Troubleshoot Edge Gateway routing

The app's status line and the `reason` field from `c1-multipass headless edge status` or a health route identify most problems.

| Message or reason | What to do |
| :--- | :--- |
| The Multipass service doesn't allow this app to control the Edge proxy. | The app was opened from a temporary location. Quit it, eject the disk image, open C1 Multipass from **/Applications**, then turn **Route AI traffic through Edge** off and on. |
| The Multipass service isn't installed on this device, or isn't responding. | Click **Open Login Items** and allow C1 Multipass, or restart the app. |
| The Multipass service isn't signed in yet. | Unlock C1 Multipass and confirm this device is registered. |
| You don't have access to an Edge. (`NO_USABLE_EDGE`) | Ask your C1 admin for access to an Edge Gateway. |
| Choose which Edge to use. (`EDGE_SELECTION_REQUIRED`) | Pick an Edge Gateway from the **Edge** list in **Settings** > **General**. |
| Your organization denied Edge access for this device. (`EDGE_GRANT_DENIED`) | Ask your C1 admin to check your Edge Gateway access and this device's registration. |
| `missing or wrong local key` | Run `eval "$(c1-multipass headless edge env)"` again. The key changed when the service restarted. |
| `unable to get local issuer certificate` | Your tool doesn't trust the Edge Gateway CA. See [Point your tools at the trust bundle](#point-your-tools-at-the-trust-bundle). |
| `unsupported inference route` | The client added a query string to the request URL. Use the egress endpoint for that client. |

## Frequently asked questions about Edge Gateway routing

<AccordionGroup>
  <Accordion title="Do I need a provider API key, such as an OpenAI key?">
    No. C1 Multipass authenticates each request to Edge Gateway as you, using this device's session. The local key only protects the loopback endpoints on your device.
  </Accordion>

  <Accordion title="Can other users on my Mac use my endpoints?">
    Not without the local key. Loopback ports are reachable by every local process, so both endpoints reject requests without the key. Edge Gateway routing is intended for single-user devices.
  </Accordion>

  <Accordion title="Why does routing keep running after the app locks?">
    Starting routing requires an unlocked app. After that, the C1 Multipass service keeps serving so long-running tools don't fail when your screen locks. Turn off **Route AI traffic through Edge** or sign out to stop it.
  </Accordion>

  <Accordion title="Can I change the local ports?">
    Not from the desktop app. It uses `127.0.0.1:18080` for inference and `127.0.0.1:18081` for egress. In scripts, read the addresses from `c1-multipass headless edge status` rather than hardcoding them.
  </Accordion>
</AccordionGroup>
