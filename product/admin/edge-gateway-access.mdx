Give people or service principals access to an Edge Gateway from its **Grants** tab. For inference, the tab groups **List models** and **Call models** into one **Inference** capability.

## Edge Gateway entitlements

Each Edge has two entitlements on its parent application:

| Entitlement | Scope | Lets the caller |
| :--- | :--- | :--- |
| **List models** | `inference.models.read` | See which models the Edge serves (`GET /v1/models`) |
| **Call models** | `inference.invoke` | Send requests to the Edge's models |

The scopes are separate: **Call models** doesn't include **List models**, and many tools list models before calling one. Adding a member to the **Inference** capability grants both entitlements together. Workload callers need both.

## Grant access to people or service principals

Add members directly from the Edge's **Grants** tab. You don't need to create an access profile for a direct grant.

  <img src="/images/product/assets/edge-grants.png" alt="The Grants tab with an Inference capability containing List models and Call models, no access profile yet, and a Members section with an Add member button."/>
</Frame>

<Steps>
<Step>
Open the Edge: **Apps** > *your app* > **Edge** > *your Edge*.
</Step>
<Step>
Click the **Grants** tab.
</Step>
<Step>
Under **Members**, select the **Inference** tab. If the Edge also serves egress, make sure you're adding members to the intended capability.
</Step>
<Step>
Click **Add member**. The **Grant access: Inference** dialog opens.
</Step>
<Step>
In **Person or service principal**, select the identities to grant access to.
</Step>
<Step>
Click **Grant access**.
</Step>
</Steps>

<Frame>
  <img src="/images/product/assets/edge-grant-access.png" alt="The Grant access: Inference dialog with a Person or service principal picker and Cancel and Grant access buttons."/>
</Frame>

The identities appear in **Members**. The **Access via** column shows why they have access, such as **Added by owner**, **Rule**, **Access profile**, or **Request**. Use the filters above the table to inspect each source.

<Note>
You can add people or service principals, but membership doesn't change the Edge's caller configuration. **People who sign in** accepts authorized human callers; **A workload** requires the configured service principal and workload federation trust. Check **Who can call** in the **Overview** checklist, expanding **Show checklist** if it's collapsed. See [Choose who can call the Edge](/product/admin/edge-gateway-setup#choose-who-can-call-the-edge).
</Note>

## Remove a direct grant

Remove an owner-added assignment from the **Members** table:

1. Open the member's **...** (more actions) menu.
2. Select **Remove from capability**.
3. Review the confirmation and click **Remove**.

This removes the owner-added assignment from the capability's entitlements. A member with another source of access can retain access through that source. For rule-based access, use **Open in Edit access** to change the rule. For access-profile membership, remove the membership in the access profile. For request-based access, use **Open request** to manage the request. **Remove from capability** is unavailable when there is no owner-added assignment to remove.

## Optional: Configure automatic membership and requests

Use an access profile when you want automatic membership, requestable access, or policies for the **Inference** capability. A direct **Add member** grant doesn't require one.

1. In the capability summary at the top of **Grants**, click **Create access profile** in the **Inference** row if no profile exists. C1 creates a profile containing both inference entitlements.
2. Click **Edit access** in that row.
3. Under **Automatic membership**, keep **Nobody** selected for no automatic membership, or select **Users with entitlements** and choose the entitlements that define membership. To follow a group, choose that group's membership entitlement.
4. Configure **Requestable**, **Request policy**, and **Revoke policy** as needed. Review any warnings about approval and removal behavior, then click **Save**.

The capability summary shows the linked **Access profile**, **Auto membership**, and **Requestable** state. Automatic membership and approval settings determine when matching users receive access and what happens when they stop matching. Other sources of access can keep a member's access active.

If the profile uses a CEL rule, click **Edit rule** to change it in the access profile. Use **Open access profile** for settings outside the **Edit access** drawer. If the summary shows **Bundle off**, configure the access profile so membership grants its bundled Edge entitlements; profile membership alone isn't enough.

## What callers see after you grant access

Once a person holds the entitlements:

- C1 Multipass lists the Edge, and its **Route AI traffic through Edge** setting can use it. See [Route other tools through C1 Multipass](/product/admin/connect-edge-gateway-multipass).
- The Edge appears under **Model endpoints** in their **AI & API** > **Inference API keys** page when **Allow long-lived API keys** is on. This setting isn't needed for the Multipass key helper. See [Use long-lived API keys](/product/admin/inference-api-keys).
