The HubSpot MCP server lets you govern access to HubSpot — contacts, companies, deals, and other CRM records — as tools your AI clients can call through C1.

You choose how users connect when you register the server:

- **Per-user OAuth** (recommended). Each person authorizes with their own HubSpot account, so every tool call runs under that user's HubSpot identity and permissions.
- **Private app token**. A single token authenticates everyone, so all tool calls reach HubSpot as one shared identity. Create the token from a dedicated service-account user so activity is attributable to C1 rather than a person.

For a deeper comparison of shared versus per-user credentials, see [Configure authentication](/product/admin/mcp-servers#configure-authentication).

## How C1 connects to HubSpot

C1 hosts the HubSpot MCP server, so your users' AI clients only ever see MCP tools — they never call HubSpot directly. When an AI client calls one of these tools, C1 makes the matching request to the HubSpot API using the credentials you configure here, then returns the result to the AI client.

The credentials you set up below are what C1 uses to call HubSpot on your users' behalf.

## Before you begin

- AI access management must be enabled for your tenant. See [Enable AI access management](/product/admin/enable-ai-access-management).
- For per-user OAuth, a HubSpot developer account that can create an app. See HubSpot's [working with OAuth](https://developers.hubspot.com/docs/apps/legacy-apps/authentication/working-with-oauth) guide.
- For a private app token, a HubSpot account with permission to create and manage private apps, which requires super admin access.

<Note>
If you don't see **HubSpot** in your MCP server catalog, [contact the C1 support team](mailto:support@c1.ai) to enable it for your tenant.
</Note>

## Option 1: Set up per-user OAuth

With per-user OAuth, you register one HubSpot app and each user authorizes individually. This keeps every action attributable to the user who took it, with only the access that user already has in HubSpot.

### Create a HubSpot app

Create an app in HubSpot and select its scopes before you configure authentication in C1.

<Steps>
<Step>
In your HubSpot developer account, create an app and give it a recognizable name such as `C1`. See HubSpot's [working with OAuth](https://developers.hubspot.com/docs/apps/legacy-apps/authentication/working-with-oauth) guide.
</Step>
<Step>
On the app's **Auth** tab, set the **redirect URL** exactly to whichever matches your C1 tenant's domain:

- Default instance: `https://accounts.conductor.one/auth/callback`
- EU data residency instance: `https://accounts.c1eu.ai/auth/callback`
</Step>
<Step>
On the same tab, add the scopes from [HubSpot scopes](#hubspot-scopes) below — the default read scopes, plus any optional scopes you need.
</Step>
<Step>
Copy the app's **Client ID** and **Client secret**.
</Step>
</Steps>

### HubSpot scopes

HubSpot treats every scope selected on the app's **Auth** tab as required, so the scopes on the app and the scopes C1 requests must match. If they don't, HubSpot shows an error on the authorization page.

**Default scopes** are read-only. C1 requests them automatically:

`crm.objects.contacts.read`, `crm.objects.companies.read`, `crm.objects.deals.read`, `crm.objects.tickets.read`, `crm.schemas.contacts.read`, `crm.schemas.companies.read`, `crm.schemas.deals.read`, `crm.schemas.tickets.read`

**Optional scopes** enable the write tools and owner lookups. To use one, select it on the HubSpot app **and** add it to the scopes field when you configure authentication in C1. Grant only what you need:

`crm.objects.contacts.write`, `crm.objects.companies.write`, `crm.objects.deals.write`, `crm.objects.tickets.write`, `crm.objects.owners.read`

<Note>
Scope changes take effect the next time a user connects. If you add a scope after users have already connected, each user must reconnect their HubSpot account to grant it.
</Note>

### Register the server with OAuth

With your HubSpot app ready, register the server and provide its credentials.

<Steps>
<Step>
Follow [Register an MCP server](/product/admin/mcp-servers#register-an-mcp-server) and select **HubSpot** from the catalog.
</Step>
<Step>
When you [configure authentication](/product/admin/mcp-servers#configure-authentication), choose per-user OAuth and enter your app's **client ID** and **client secret**.
</Step>
<Step>
**Optional.** Add any optional scopes to the scopes field. The field is editable and is pre-filled with the default scopes.
</Step>
<Step>
Save your changes. The first time a user calls a HubSpot tool from their AI client, they're prompted to connect their HubSpot account.
</Step>
</Steps>

## Option 2: Use a private app token

A private app token authenticates every user as one shared HubSpot identity. Use this when per-user attribution in HubSpot isn't required.

### Create a HubSpot private app token

Create a private app in HubSpot to generate the access token C1 uses to call HubSpot.

<Steps>
<Step>
In HubSpot, create a private app and select **Create a private app**. See HubSpot's [private apps](https://developers.hubspot.com/docs/guides/apps/private-apps/overview) docs for the navigation path and required super admin access.
</Step>
<Step>
On the **Basic info** tab, give the app a recognizable name such as `C1`.
</Step>
<Step>
On the **Scopes** tab, grant only the scopes you need, such as the default read scopes listed under [HubSpot scopes](#hubspot-scopes).
</Step>
<Step>
Select **Create app**, then copy the **access token**. Treat the token like a password.
</Step>
</Steps>

### Register the server with a token

With your token ready, register the server and provide your credentials.

<Steps>
<Step>
Follow [Register an MCP server](/product/admin/mcp-servers#register-an-mcp-server) and select **HubSpot** from the catalog.
</Step>
<Step>
When you [configure authentication](/product/admin/mcp-servers#configure-authentication), choose **Bearer token** and paste your private app access token.
</Step>
<Step>
Save your changes. C1 starts a sync that discovers the tools the HubSpot server exposes.
</Step>
</Steps>

## How HubSpot credentials are shared

How HubSpot sees your users' activity depends on the method you chose:

- **Per-user OAuth.** Each user authorizes with their own HubSpot account, so tool calls run under that user's HubSpot identity and inherit only the access they already have. HubSpot attributes each action to the individual user.
- **Private app token.** Every user's tool calls use the one token you provided, so HubSpot sees a single shared identity. C1 still attributes each call to the individual user in the [AI tool usage audit log](/product/admin/audit-ai-tool-usage). For a shared production setup, create the token from a dedicated service-account user so activity is attributable to C1 rather than a person.

For how shared and per-user credentials work across MCP servers, see [Configure authentication](/product/admin/mcp-servers#configure-authentication).

## Discover and govern tools

After you register the server, C1 runs tool discovery against HubSpot. Discovered tools appear on the server's **Tools** tab.

Each tool starts as either **Pending review** or automatically **Approved**, depending on the option chosen when the server was set up or your tenant's default tool settings in **AI** > **MCPs** > **Settings**. See [Require tool approval](/product/admin/enable-ai-access-management#require-tool-approval) and [Default tool classification](/product/admin/enable-ai-access-management#default-tool-classification).

Before anyone can call a HubSpot tool, it must be approved, added to a toolset, and bound to an access profile. Continue to [Govern tools and toolsets](/product/admin/tools-and-toolsets) to set this up.

<Note>
Tool discovery runs even if your credentials are incorrect, so seeing discovered tools doesn't confirm that authentication is working. You confirm your HubSpot credentials when an approved user successfully calls a HubSpot tool from their AI client.
</Note>

## Manage your HubSpot credentials

- **Rotate the OAuth client secret** in your HubSpot app's **Auth** tab, then update the secret on the server's authentication settings in C1.
- **Rotate the access token** by rotating it in the private app's settings in HubSpot, then update the token on the server's authentication settings in C1.
- **Adjust access** by editing the app's scopes in HubSpot and, for per-user OAuth, the scopes field in C1.
