Every Edge Gateway has an endpoint, an audience, and an inference resource that callers use to request tokens and send model requests. Find these values on the Edge's **Overview** tab, then point callers to the connection method that fits their tool.

## Find the Edge's connection details

The **Connection details** card fills in once the Edge is turned on.

<Steps>
<Step>
Open the Edge: **Apps** > *your app* > **Edge** > *your Edge*.
</Step>
<Step>
On the **Overview** tab, scroll to **Connection details**.
</Step>
</Steps>

<Frame>
  <img src="/images/product/assets/edge-connection-details.png" alt="The Connection details card showing the Audience, the Inference resource, and the inference.models.read and inference.invoke scopes."/>
</Frame>

| Value | Format | Used for |
| :--- | :--- | :--- |
| **Audience** | `https://<your-org>.edge.<your-zone>` | The token audience. All Edges in your tenant share it. |
| **Inference resource** | `https://<your-org>-inference.edge.<your-zone>/api/v1/apps/<app-id>/edges/<edge-id>` | Identifies this Edge when a caller requests a token |
| **Inference endpoint** | The inference resource up to, but not including, `/api` | The base URL callers send model requests to |
| **Scopes** | `inference.models.read`, `inference.invoke` | The access a token carries; matches the Edge's entitlements |

The app ID and Edge ID also appear in the Edge's URL in C1.

## Choose how callers connect to the Edge

The **How to connect** section on the **Overview** tab gives each person ready-to-copy settings. Both methods run through C1 Multipass, which signs in as the person, so there's no key to store or rotate.

<Frame>
  <img src="/images/product/assets/edge-how-to-connect.png" alt="The How to connect section showing Loopback with Desktop and Headless options and Claude Code, Codex, and Other tabs, and Direct with the Bearer keys allowed status."/>
</Frame>

| Method | How it works | Requires |
| :--- | :--- | :--- |
| **Loopback** | The tool points at `127.0.0.1` on the person's device. C1 Multipass signs in as them and sends the traffic through the Edge. | C1 Multipass with **Route AI traffic through Edge** on |
| **Direct** | The tool points at the Edge's inference endpoint. C1 Multipass gives the tool a short-lived key and renews it. | C1 Multipass, and **Inference Bearer tokens** allowed on the Edge |

Each method has tabs for **Claude Code**, **Codex**, and **Other**, with the commands or settings to copy. Expand **Set up Multipass** for the one-time device setup each person does first.

For step-by-step instructions, send callers to:

- [Connect with C1 Multipass](/product/admin/connect-edge-gateway-multipass), for the Loopback method.
- [Use Claude Code](/product/admin/claude-code-edge-gateway-multipass), for the Direct method with Claude Code.
- [Inference API keys](/product/admin/inference-api-keys), for callers without C1 Multipass, such as scripts and servers. This also requires **Inference Bearer tokens**.

## Connect your own application to the Edge

An application can call the Edge directly by exchanging its signed-in user's C1 identity for an Edge token. Request a token for the **Audience**, with the **Inference resource** as the resource and the scopes the caller needs, then send model requests to the inference endpoint with that token. See [Enterprise-managed authorization](/product/admin/enterprise-managed-authorization/overview) for how C1 issues these tokens.

## Troubleshoot Edge connection details

| Symptom | What to do |
| :--- | :--- |
| **Inference resource** and **Scopes** show "—" | Turn on the Edge. These values appear once it's on. |
| "Short-lived keys are off for this Edge" under **Direct** | Turn on **Inference Bearer tokens** on the **Inference** tab, or use **Loopback**. |
| Callers see "You don't have access to an Edge" | Grant them **List models** and **Call models**. See [Grant access to an Edge](/product/admin/edge-gateway-access). |
| Callers can list models but requests fail with `403` | Grant **Call models** as well as **List models**. |
