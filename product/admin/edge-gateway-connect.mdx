Find the values callers need to connect to your Edge Gateway, then share the settings for their tool. The Edge's **Overview** tab provides connection details and ready-to-copy configuration.

## Find the Edge's connection details

The **Connection details** card fills in once the Edge is turned on.

<Steps>
<Step>
Open the Edge: **Apps** > *your app* > **Edge** > *your Edge*.
</Step>
<Step>
On the **Overview** tab, scroll to **Connection details**.
</Step>
</Steps>

<Frame>
  <img src="/images/product/assets/edge-connection-details.png" alt="The Connection details card showing the Audience, the Inference resource, and the inference.models.read and inference.invoke scopes."/>
</Frame>

| Value | Format | Used for |
| :--- | :--- | :--- |
| **Audience** | `https://<your-org>.edge.<your-zone>` | The token audience. All Edges in your tenant share it. |
| **Inference resource** | `https://<your-org>-inference.edge.<your-zone>/api/v1/apps/<app-id>/edges/<edge-id>` | Identifies this Edge when a caller requests a token |
| **Inference endpoint** | The inference resource up to, but not including, `/api` | The base URL callers send model requests to |
| **Scopes** | `inference.models.read`, `inference.invoke` | The access a token carries; matches the Edge's entitlements |

The app ID and Edge ID also appear in the Edge's URL in C1.

## Connect your tools

On the **Overview** tab, use **Connect your tools** and choose **Claude Code**, **Codex**, or **Other**. Follow **Set up Multipass** before copying a tool's settings.

| Tool or host | How it connects | Next step |
| :--- | :--- | :--- |
| **Claude Code** | Calls the Edge over HTTPS using a Multipass `apiKeyHelper` | Copy the generated settings, or follow [Use Claude Code](/product/admin/claude-code-edge-gateway-multipass) |
| **Codex** on a desktop | Calls the Edge over HTTPS using command-based authentication | Use Codex 0.118 or later and copy the generated provider and profile settings |
| **Other** tools and SDKs | Use Multipass local endpoints | Follow [Connect with C1 Multipass](/product/admin/connect-edge-gateway-multipass) |
| Enrolled service hosts | Use the Multipass fleet CLI and local endpoints | Follow the Linux service steps in [Connect with C1 Multipass](/product/admin/connect-edge-gateway-multipass#turn-on-edge-gateway-routing) |

The Claude Code and Codex key helpers renew short-lived tokens automatically. They don't require **Allow long-lived API keys**.

### Configure Codex on a desktop

Use Codex 0.118 or later for command-based provider authentication. Copy the **Codex** tab's configuration into `~/.codex/config.toml`, preserving your existing configuration. The configuration has this form; replace the inference host, app ID, Edge ID, and model route ID with your Edge's values:

```toml
[profiles.edge]
model_provider = "edge"
model = "<responses-route-id>"

[model_providers.edge]
name = "Edge"
base_url = "https://<inference-host>/v1"
wire_api = "responses"
requires_openai_auth = false
supports_websockets = false

[model_providers.edge.auth]
command = "c1-multipass"
args = ["inference", "helper", "--edge-url", "https://<inference-host>", "--inference-resource", "https://<inference-host>/api/v1/apps/<app-id>/edges/<edge-id>", "--dial-only"]
timeout_ms = 10000
refresh_interval_ms = 180000
```

The helper uses the inference origin, while the provider base URL adds `/v1`. If `c1-multipass` isn't on Codex's `PATH`, use the command's full path. Merge these tables rather than defining an existing table twice.

Start Codex with the generated profile:

```bash
codex --profile edge
```

Use a route exposed by your Edge that supports the Responses API. Don't substitute a provider model name unless it is also the route ID.

### Configure Codex on an enrolled server

On an enrolled Linux host, use the **Codex** tab's **Server** instructions instead of the desktop command-auth profile. Select the Edge, start local routing, and load its environment into the shell:

```bash
c1-multipass-fleet edge select <app-id>/<edge-id>
c1-multipass-fleet edge start
eval "$(c1-multipass-fleet edge env)"
codex -m <responses-route-id>
```

This path uses `OPENAI_BASE_URL` and `OPENAI_API_KEY` from the local routing environment. Start Codex from the same shell. See [Connect with C1 Multipass](/product/admin/connect-edge-gateway-multipass) for the local endpoints and trust bundle.

### Optional: Use a long-lived inference API key

For clients that can't use Multipass, an admin can turn on **Allow long-lived API keys**. The **Long-lived API keys (advanced)** section then provides settings for a `c1llm_` key. See [Inference API keys](/product/admin/inference-api-keys).

## Connect your own application to the Edge

An application can call the Edge directly by exchanging its signed-in user's C1 identity for an Edge token. Request a token for the **Audience**, with the **Inference resource** as the resource and the scopes the caller needs, then send model requests to the inference endpoint with that token. See [Enterprise-managed authorization](/product/admin/enterprise-managed-authorization/overview) for how C1 issues these tokens.

## Troubleshoot Edge connection details

| Symptom | What to do |
| :--- | :--- |
| **Inference resource** and **Scopes** show "—" | Turn on the Edge. These values appear once it's on. |
| A long-lived inference API key is rejected | Check **Allow long-lived API keys** on the **Inference** tab. This setting doesn't control the Multipass key helper. |
| Callers see "You don't have access to an Edge" | Grant them **List models** and **Call models**. See [Grant access to an Edge](/product/admin/edge-gateway-access). |
| Callers can list models but requests fail with `403` | Grant **Call models** as well as **List models**. |
