Run Codex through your organization's Edge Gateway without a provider API key. On a desktop, Codex uses C1 Multipass command-based authentication to renew short-lived tokens and calls the Edge directly over HTTPS. On an enrolled Linux server, Codex uses the Multipass fleet CLI's local routing endpoints.

## Before you begin with Codex and Edge Gateway

Confirm these prerequisites before configuring Codex:

- Codex 0.118 or later is installed.
- On macOS, C1 Multipass and its command line tool are installed, signed in to your tenant, the device registered, and the app unlocked. Follow [Set up Multipass](/product/admin/connect-edge-gateway-multipass#set-up-multipass). The inference-helper CLI isn't available on Windows.
- On Linux servers, an enrolled Multipass runtime and `c1-multipass-fleet` are available. Follow the [Linux service routing setup](/product/admin/connect-edge-gateway-multipass#turn-on-edge-gateway-routing).
- Your C1 admin has granted you **List models** and **Call models** on an Edge with a route whose native format is **OpenAI Responses** and whose model supports your Codex workload. Set Codex's model to that route's **Route ID**. OpenAI Chat and Anthropic Messages routes aren't interchangeable with a Responses route. For an OpenAI model, select the **Responses** variant, not **Chat**. See [Configure inference routes](/product/admin/edge-gateway-inference-routing) and [Grant access to an Edge](/product/admin/edge-gateway-access).
- Make sure **Cross-App Access** is on under **Settings** > **Cross-App Access** so Multipass can get Edge tokens for people. The Edge's **Overview** warns if it's off. If the setting isn't available, contact the C1 Support team. See [Enable enterprise-managed authorization](/product/admin/enterprise-managed-authorization/enable).

The Multipass helper renews short-lived tokens automatically. It doesn't require **Allow long-lived API keys**. Use the desktop configuration or the enrolled-server configuration below, not both for the same Codex session.

## Configure Codex on a desktop

Use Codex 0.118 or later for command-based provider authentication. On the Edge's **Overview** tab, open **Connect your tools** > **Codex** and select **Desktop**. Copy the configuration into `~/.codex/config.toml`, preserving your existing configuration. You don't need to turn on local routing or load its environment for this path.

<Frame>
  <img src="/images/product/assets/edge-how-to-connect-codex.png" alt="The Codex tab with Desktop selected and the start of config.toml, showing the edge profile, Edge model provider, and a generated example model."/>
</Frame>

The screenshot's model is a generated example. Replace it with a Responses-native route published on your Edge.

The configuration has this form; replace the inference host, app ID, Edge ID, and model route ID with your Edge's values. See [Find the Edge's connection values](/product/admin/edge-gateway-connect#find-the-edges-connection-details).

```toml
[profiles.edge]
model_provider = "edge"
model = "<responses-route-id>"

[model_providers.edge]
name = "Edge"
base_url = "https://<inference-host>/v1"
wire_api = "responses"
requires_openai_auth = false
supports_websockets = false

[model_providers.edge.auth]
command = "c1-multipass"
args = ["inference", "helper", "--edge-url", "https://<inference-host>", "--inference-resource", "https://<inference-host>/api/v1/apps/<app-id>/edges/<edge-id>", "--dial-only"]
timeout_ms = 10000
refresh_interval_ms = 180000
```

The helper uses the inference origin, while the provider base URL adds `/v1`. If `c1-multipass` isn't on Codex's `PATH`, use the command's full path. Merge these tables rather than defining an existing table twice.

Start Codex with the generated profile:

```bash
codex --profile edge
```

Codex now uses the Edge profile and its short-lived credentials. Use a route whose native format is OpenAI Responses. Don't substitute a provider model name unless it is also the route ID.

If you previously loaded a local routing environment, remove its uppercase `HTTPS_PROXY` setting for this direct connection:

```bash
env -u HTTPS_PROXY codex --profile edge
```

This removes only the uppercase `HTTPS_PROXY` variable for this command, not other proxy variables or system proxy settings.

## Configure Codex on an enrolled server

On an enrolled Linux host, use the **Codex** tab's **Server** instructions instead of the desktop command-auth profile. Select the Edge, start local routing, and load its environment into the shell:

```bash
c1-multipass-fleet edge select <app-id>/<edge-id>
c1-multipass-fleet edge start
eval "$(c1-multipass-fleet edge env)"
codex -m <responses-route-id>
```

This path uses `OPENAI_BASE_URL` and `OPENAI_API_KEY` from the local routing environment. Start Codex from the same shell. The model must still be a Responses-native route ID. See [Route other tools through C1 Multipass](/product/admin/connect-edge-gateway-multipass) for the local endpoints, Linux service configuration, and trust bundle for outbound HTTPS traffic.

## Troubleshoot Codex with Edge Gateway

Use the symptom to check the client configuration or ask your C1 admin to check the route:

| Symptom | What to do |
| :--- | :--- |
| Codex doesn't recognize command-based authentication | Use Codex 0.118 or later. |
| Codex can't find `c1-multipass` | Use the installed command's full path in `[model_providers.edge.auth]`. See [Set up Multipass](/product/admin/connect-edge-gateway-multipass#set-up-multipass). |
| The helper reports a missing session or refuses the connection | Open and unlock Multipass, and confirm the device is registered. Ask your admin to check Cross-App Access and your **List models** and **Call models** grants. |
| The route or model isn't found | Use the Edge's exact **Route ID**, not the provider model name. Confirm the route is published and the Edge is on. |
| A request fails with a format or compatibility error | Select a route whose native format is OpenAI Responses and a model that supports the requested Codex features. Chat and Messages routes don't accept Responses requests. |
| Desktop Codex still uses local routing | Check for `HTTPS_PROXY` from a previous routing session. Use the direct-launch command above and check other proxy settings separately. |
| Server Codex doesn't use the selected Edge | Load `c1-multipass-fleet edge env` and start Codex from that same shell, without selecting the desktop `edge` profile. See [Troubleshoot Edge Gateway routing](/product/admin/connect-edge-gateway-multipass#troubleshoot-edge-gateway-routing). |

For clients that can't use Multipass, see [Use long-lived API keys](/product/admin/inference-api-keys). An admin must turn on **Allow long-lived API keys** before those clients can use a `c1llm_` key.
